Project 01 · Siemens EDA Technical owner · 2022 to present

Design Packager: reproducible packaging of verification runs

Design Packager is a horizontal tool shared across Siemens product lines. Given one run of a verification tool, it discovers every command, file and environment variable involved, builds a dependency graph, and produces a self-contained package that reproduces the run anywhere.

It is built to be extensible and scalable. A new tool is integrated by introducing an XML file describing its commands; the packager reads that file and handles the parsing, processing and packaging of the design internally. That core is common to all tools and a black box to them, and the XML interface is the contract between each tool and the packager. Mariam owns the tool end to end, from customer requests to release, integrated new tools through this interface, and added ARM platform support.

Project 02 · QuestaSim parallel simulation initiative C++20 coroutines · thread pool · research prototype

Parallel Simulation Kernel: a coroutine-based discrete-event simulator

A prototype that decentralizes the execution of simulation processes from a single kernel thread to several worker threads. At every simulation time slot, millions of processes and events become ready, and most of them are independent, so they can run in parallel instead of one after another.

The kernel is written from scratch in modern C++. Processes are coroutines that suspend into a scheduling region and resume later in simulation time, a thread pool executes each region's events on a deterministic partition, and synchronization is kept to minimal, well-defined sync points (region barriers and commit phases) chosen to preserve correctness and deterministic results while leaving the parallel phase free to run.

Decentralized execution

One kernel dispatches; several threads execute.

Millions of events per slot

Independent processes in a time slot run in parallel.

Minimal sync points

Region barriers and commit phases keep results correct and deterministic.

Project 04 · QuestaSim parallel simulation initiative CUDA · performance prototype

GPU-accelerated simulation prototype

After the multithreaded CPU work, Mariam designed a proof of concept around what GPUs are good at: the same operation applied to a large amount of data at once. She identified the kernel function that the simulator applies repeatedly over large data, the SIMD-shaped part of the workload, and restructured that phase to run as CUDA kernels, with partitioning before and a merge back into simulator state after.

The result was a large performance gain over both the CPU prototype and standard Questa execution, with results kept functionally identical.
